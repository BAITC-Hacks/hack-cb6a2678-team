## Разделение данных

1. Модели для сравнения поясов обучены на 20.01.2024–31.10.2025. Внутренний подбор числа
   деревьев — предшествующие 60 дней, все преобразования обучались только на обучающей части.
   Внешняя валидация: 01.11–31.12.2025.
2. Поправки среднего обучены на ноябрьских независимых прогнозах этой модели;
   метод none/additive/scale/affine выбран по nMAE декабря, отдельно D+1/D+2.
3. Интервал расширен по 80%-квантилю max(p10−actual, actual−p90) декабря,
   ранг ceil((n+1)*0.8), отдельно по заблаговременности. Это эмпирическая калибровка
   временного ряда: строгая независимость часов не заявляется.
4. Пороги предупреждений — 90/90/95-е процентили статистик полных выпусков ноября–декабря.
   Январь и февраль не использовались для выбора параметров.
5. Тестовая модель переобучена по 31.12.2025, рабочая — по 31.01.2026.
   Деревья/поправки/пороги заморожены; early stopping на январе нет.
   Последние обучающие часы: 2025-12-31T18:00:00Z и 2026-01-31T18:00:00Z.

## Контракт и ограничения

Ответы трёх маршрутов соответствуют YAML v2.0. Рабочие версии:
t1 lgbm-6a5550b3cb92061f, t2 lgbm-0d713e942bf918b8.
Версия зависит от содержимого joblib и стабильна при перезапуске.
Обнаруженные особенности (сам YAML не менялся):

- Live допускается в запросе, но после D 12:00 подтвердить его историческую доступность нельзя → 503.
  Leakage_mode остаётся strict/standard по enum. Standard также отвергается, если граница позже D 12:00.
- Previous Runs не отдаёт точный ID/время публикации запуска. Weather_issued_before_utc —
  верхняя граница max(target_utc − N×24h), не точная метка. Основание:
  [официальная семантика заблаговременностей](https://open-meteo.com/en/docs/previous-runs-api).
  Для 31.01.2026 граница 2026-01-30T18:00:00Z, на 13 часов раньше выпуска.
- В YAML site обязателен, прежний сервис при пропуске выбирает turbine_1.
  Дополнительный режим сохранён из-за требования не менять запрос; контрактные запросы поддержаны.
- В ModelInfo новые поля не перечислены в required. Тесты дополнительно требуют их наличия.
- Старый status=error заменён на critical из enum. Для соблюдения p10 ≤ forecast ≤ p90
  границы расширяются, сам средний прогноз не меняется.

## C: переносимость тестов упаковки

В tests/test_packaging.py SHA-256 датасетов проверяется после замены CRLF на LF;
эталоны соответствуют LF-версии файлов в Git. Изменение значений CSV по-прежнему
ломает проверку. Сохранённые хэши в отчётах обучения относятся к исходным байтам
CSV при обучении и не пересчитывались.

Зависимости разбираются через packaging.requirements.Requirement: точный пин
обязателен для каждой строки, установленная версия проверяется только при выполнении
её маркера окружения. colorama требуется только при sys_platform == 'win32'.
Регрессии проверяют LF/CRLF, изменение значений, маркеры Linux/macOS/Windows,
отсутствующие пакеты, неверные версии и незакреплённые зависимости.

Проверка упаковки: python -m pytest -q tests/test_packaging.py — 13 тестов.
Полный набор: 56 тестов прошли на Windows / Python 3.14; условия Linux/macOS
проверены с подменой маркеров окружения, без нативного запуска на этих ОС.
