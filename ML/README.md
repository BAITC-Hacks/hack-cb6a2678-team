# windml — ML-инструмент прогноза выработки ВЭС (HackAlem AI)

Обученные модели для двух турбин, результаты отдельного январского теста и
контракт FastAPI ↔ Java-бэкенд: [TRAINING.md](TRAINING.md).

ML-часть решения кейса «Agentic AI для прогнозирования выработки ВЭС».
Пакет строит почасовой прогноз нормированной мощности турбины на 48 часов
(сутки D+1 и D+2) по архивным прогнозам погоды из открытых источников и
предоставляет AI-агенту набор инструментов (tools) с JSON-схемами.

## Как это работает

```
Open-Meteo Previous Runs API         SCADA (10 мин → 1 ч)
(ECMWF IFS, GFS, ICON; прогнозы,      ├─ очистка простоев
 выпущенные N суток назад)            ├─ эмпирическая кривая мощности (изотоническая)
          │                           └─ целевая переменная
          ▼
  признаки: ветер 10/100 м по 3 моделям, ансамбль (среднее/разброс),
  сдвиг ветра, направление, плотность воздуха, сглаживание фазовых ошибок,
  календарь, заблаговременность
          │
          ├─► квантильное отображение ветра NWP → ветер на гондоле
          ├─► кривая мощности → «физический» прогноз (признак + бейзлайн)
          ▼
  LightGBM: mean (с монотонным ограничением по физ. признаку) + квантили p10/p50/p90
          ▼
  прогноз 48 ч + автоматический анализ (статус, рекомендация агенту)
```

### Защита от утечки будущего

ТЗ требует использовать прогнозы погоды, доступные на момент выпуска, а не
фактическую погоду. Поэтому источник — **Open-Meteo Previous Runs API**: для
каждого часа он хранит значение, спрогнозированное моделью N суток назад
(`<переменная>_previous_dayN`, архив с января 2024).

Выпуск в день D (12:00 местного) → цель: сутки D+1 и D+2.
Режим `strict` (по умолчанию): для D+1 берётся `previous_day2`, для D+2 — `previous_day3`,
т.е. только прогнозы, гарантированно опубликованные до момента выпуска.
Режим `standard` (`previous_day1/2`) точнее, но ближе к границе — переключается в `windml/config.py`.
Модель обучается на тех же «старых» прогнозах, что и используются в бою, поэтому
она сама учится исправлять ошибки модели погоды для данной заблаговременности.

SCADA-факт на момент выпуска не используется как признак: при заблаговременности
12–60 ч инерционность мощности бесполезна (корреляция с лагом 24 ч ≈ 0.1), а за
тестовый период факт недоступен.

### Факты о данных (turbine_1)

* 10-минутные данные 2023-03-11 … 2026-01-31, ≈23.7 тыс. часов, время местное (Asia/Almaty,
  учтён переход UTC+6 → UTC+5 от 01.03.2024).
* 149 часов с признаками простоя/ограничения (ветер > 6 м/с, мощность < 2%) — исключаются из обучения.
* Кривая мощности по фактическому ветру даёт nMAE ≈ 3.2% — это «потолок» при идеальном
  прогнозе ветра. Персистенция (значение сутки назад) — nMAE ≈ 38%. Вся сложность задачи —
  в ошибке прогноза погоды, поэтому модель строится вокруг NWP и её коррекции.

## Установка и запуск

```bash
pip install -r requirements.txt
export WINDML_ROOT=$(pwd)          # корень проекта (по умолчанию определяется сам)

python -m windml train                                   # скачать архив погоды (кэш) + обучить
python -m windml info                                    # метрики валидации
python -m windml forecast --date 2026-01-31              # один выпуск (48 ч) + анализ
python -m windml backtest --start 2026-01-31 --end 2026-02-27   # весь тестовый период
python -m windml backtest --start 2026-01-01 --end 2026-01-29   # проверка качества на факте
python -m pytest -q tests                                # офлайн-тесты (без интернета)
```

Первое обучение делает ≈75 запросов к Open-Meteo (3 модели × 25 месяцев), дальше всё
берётся из `data/cache/`. Бесплатный лимит Open-Meteo (10 000 запросов/сутки) с запасом.

## Результаты

* `outputs/forecasts/forecast_<D>.csv` + `.json` — выпуск: 48 строк, метаданные, анализ.
* `outputs/backtest/all_issues.csv` — все выпуски (каждый час покрыт дважды: lead_day 1 и 2).
* `outputs/backtest/final_hourly_forecast.csv` — итоговый ряд: для каждого часа самый свежий выпуск.
* `models/wind_model.json` — метрики валидации, важность признаков, кривая мощности.

Колонки прогноза: `forecast` (основной, MSE-оптимальный), `p10/p50/p90`, `lead_day`,
`pc_baseline` (физический прогноз), `ens_ws_mean/std` (ветер и разброс моделей погоды).
Мощность — доля номинала (0…1), как в исходных данных.

## API для агента

```python
from windml.tools import TOOL_SCHEMAS, openai_schemas, call_tool
result_json = call_tool("run_power_forecast", {"issue_date": "2026-01-31"})
```

`call_tool` никогда не бросает исключений — ошибки приходят как `{"error": ...}`.

| Инструмент | Что делает | Ключевые поля ответа |
|---|---|---|
| `get_weather_forecast` | Загружает NWP на момент выпуска | `models_ok`, `models_failed`, `weather_hash`, средний ветер |
| `run_power_forecast` | Полный цикл: погода → модель → 48 ч → анализ | `hourly[]`, `analysis`, `weather_hash`, `file` |
| `analyze_forecast` | Проверка готового прогноза | `status`, `recommended_action`, `issues`, `stats` |
| `check_weather_update` | Изменились ли входные данные | `updated`, `new_hash` |
| `evaluate_forecast` | Сравнение с фактом | nMAE, nRMSE, bias, покрытие p10–p90 |
| `run_backtest` | Скользящий выпуск за период | файлы + метрики |
| `train_model` / `get_model_info` | Переобучение / паспорт модели | метрики валидации, топ-признаки |

`recommended_action` — подсказка агенту для следующего шага:
`accept` — принять; `accept_and_recheck_on_update` — принять, но проверить обновление
погоды и пересчитать (большой разброс между моделями, нет одной из моделей);
`rerun_with_fallback` — прогноз неполный, сменить источник (`live`) или набор моделей.

Пример цикла агента (детерминированный и через Claude tool use) — `agent_example.py`.

## Структура

```
windml/
  config.py      координаты, часовой пояс, модели погоды, режим утечки
  data.py        загрузка SCADA, часовая агрегация, флаги простоев
  weather.py     провайдеры Open-Meteo (previous runs / live / mock), кэш, сборка по lead_day
  features.py    признаки из NWP
  powercurve.py  кривая мощности, квантильное отображение ветра
  model.py       гибрид физика + LightGBM, квантили, валидация, сохранение
  analysis.py    автоматический анализ прогноза
  metrics.py     nMAE, nRMSE, bias, pinball, покрытие интервала
  pipeline.py    обучение, выпуск, бэктест
  tools.py       инструменты для агента + JSON-схемы + call_tool
  cli.py         командная строка
tests/           офлайн-тесты (мок Open-Meteo, проверка отсутствия утечки)
agent_example.py пример интеграции с агентом
```
