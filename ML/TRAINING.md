# Обученные модели и HTTP API

Обучено 23.09.2026 на двух добавленных CSV. Фактические данные в обоих файлах
заканчиваются **31.01.2026**, несмотря на февраль в названиях файлов.

| Модель | Записей CSV | Обучающих строк (час × горизонт) | nMAE на январском тесте | nRMSE |
|---|---:|---:|---:|---:|
| turbine_1 | 142 360 | 32 216 | 19,99% | 25,35% |
| turbine_2 | 149 499 | 34 754 | 20,19% | 25,86% |

Ошибки выражены в процентах **номинальной мощности**, а не фактической выработки.
Тест: 01–31 января 2026, 744 уникальных часа, каждый оценён для D+1 и D+2.
Тестовые модели обучены по 31.12.2025; подбор числа деревьев проводился на
предшествующих 60 днях. Январские данные не участвовали в обучении тестовых моделей.
После оценки рабочие модели переобучены по 31.01.2026 включительно.

Использованы LightGBM, эмпирическая кривая мощности, архивные прогнозы
ECMWF/GFS/ICON из локального кэша, режим `strict`. Данные 2023 года не включены:
первые доступные погодные прогнозы в кэше — 20.01.2024.
Простои исключались из обучения, но включались в оценку.

**Допущение для turbine_2:** использована погода площадки turbine_1
(43.645150, 78.535604). Совпадение площадок пока не подтверждено.
При других координатах второй турбины нужно получить соответствующую погоду
и переобучить модель. Это допущение записано в модели и возвращается HTTP API.

Модели завышают мощность в среднем примерно на 9,7–9,9 процентного пункта на
январском тесте. Интервал p10–p90 покрывает 68–70% наблюдений вместо номинальных
80%; его нельзя считать откалиброванной гарантией. Бейзлайн постоянной средней
мощности имеет nMAE около 30,3%.

## Артефакты

- `models/wind_model.joblib` — рабочая модель turbine_1 (используется прежними tools).
- `models/wind_model_turbine_2.joblib` — рабочая модель turbine_2.
- Соседние `.json` — параметры, происхождение данных, метрики.
- `outputs/training/<site>/report.json` — полный отчёт.
- `outputs/training/<site>/evaluation_model.joblib` — модель до январского теста.
- `outputs/training/<site>/test_predictions.csv` — прогнозы и фактическая мощность теста.
- `outputs/training/<site>/forecast_next_48h.csv` — пример прогноза на 1–2 февраля;
  фактических значений за февраль в CSV нет.
- `outputs/training/turbine_1/previous_models/` — резервная копия предыдущей модели.

## Связь бэкенда с ML

```text
Backend :8080 POST /ml/forecast
   → HTTP → FastAPI :8000 POST /v1/forecast
   → архивный/живой прогноз погоды → обученная модель → JSON из 48 значений
```

Запуск ML-сервиса из корня проекта:

```powershell
python -m uvicorn windml.api:app --host 127.0.0.1 --port 8000
```

Swagger: `http://127.0.0.1:8000/docs`.
Запуск Java-бэкенда описан в `spring-agent/README.md`.
Его `WINDML_URL` по умолчанию — `http://localhost:8000`.

Прямой запрос к ML (для запроса через Java замените URL на `http://localhost:8080/ml/forecast`):

```powershell
$body = @{site='turbine_2'; issue_date='2026-01-31'; weather_source='previous_runs'} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/v1/forecast -ContentType application/json -Body $body
```

Ответ содержит `site`, даты, `model_trained_at`, происхождение погоды,
`weather_site_assumption`, анализ и `hourly` из 48 записей:
`time`, `lead_day`, `forecast`, `p10`, `p50`, `p90`.
Мощность нормирована в диапазон 0–1. Для прогноза на текущую дату задайте
`weather_source='live'` и текущий `issue_date`.

- `GET /health` — доступность FastAPI.
- `GET /v1/models` — список моделей и наличие файлов.
- `GET /v1/models/{site}` — паспорт модели.
- `POST /v1/forecast` — типизированный прогноз; неверный ввод → 422,
  модель/погода недоступна → 503.
- `POST /tools/{name}` — прежний интерфейс AI-агента, работает с turbine_1.
- Java: `GET /ml/models`, `GET /ml/models/{site}`, `POST /ml/forecast`.
  Прямой маршрут не вызывает LLM; существующие `/agent/*` продолжают работать.

## Проверка

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest -q tests
```

HTTP-тесты проверяют обе сохранённые модели на реальном кэше погоды,
48-часовой ответ, квантили, валидацию запросов и ошибки недоступности.
Тесты FastAPI используют [официальный TestClient](https://fastapi.tiangolo.com/tutorial/testing/).

Для сквозной проверки настоящего HTTP-соединения после сборки Java:

```powershell
python tests/smoke_backend.py
```

Проверка временно запускает оба сервиса, получает прогнозы двух турбин через
Java-бэкенд, проверяет HTTP 422 и 503 и останавливает запущенные процессы.
Результаты — `outputs/integration/summary.json`. LLM в этой проверке не вызывается.

## Соответствие описанному ТЗ: что ещё не закрыто

ML-модели обучены, прогноз на 48 часов и FastAPI работают. Полного соответствия
архитектуре из сообщения команды пока нет:

1. Координаты turbine_2 требуют подтверждения; её модель пока предварительная.
2. Погоду получает Python через **Previous Runs**, а не бэкенд через Single Runs.
   Используются архивные прогнозы, не фактическая погода. Однако точные метки
   `weatherIssuedAt`/доступности конкретного запуска не сохранены. Для аудита
   нужно сохранять реальные метаданные запуска, а не вычислять фиктивную дату
   как `targetTime - previous_day`.
3. Текущий контракт: `POST /v1/forecast` принимает дату и турбину, Python получает
   погоду сам. `POST /predict`, принимающего погодные значения от бэкенда, нет.
   При внедрении этого контракта нужно согласовать модели NWP, единицы, высоты,
   часовой пояс и горизонт с обучением, иначе входы будут отличаться от обучающих.
4. Полная серия ежедневных выпусков за февраль для обеих турбин в рамках этого
   обучения не сформирована. Есть пример на 1–2 февраля; факта за февраль нет.
5. Модели прогнозируют долю номинальной мощности каждой турбины. Чтобы получить
   общую мощность станции в МВт и энергию за час в МВт·ч, нужны номиналы турбин.

Отдельно от ML: текущий Java-агент настроен на Anthropic, а не Ollama;
ежедневное расписание отключено по умолчанию; периодических ревизий каждые
6 часов нет. Поэтому описание всей системы как уже готовой и автономной
не соответствует текущему коду.

Семантика погодных архивов:
[Previous Runs](https://open-meteo.com/en/docs/previous-runs-api),
[Single Runs](https://open-meteo.com/en/docs/single-runs-api).
