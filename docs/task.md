# ТЗ хакатона: Agentic AI для прогнозирования выработки ВЭС

Источник — документ организаторов HackAlem AI. Ниже — полный текст задачи и критерии, плюс наши пояснения.

## Задача

Разработать Agentic AI-систему для прогнозирования **почасовой** выработки ветроэлектростанции (ВЭС) на горизонте **24–48 часов**.

Даны координаты и исторические данные работы ВЭС с **марта 2023 по 31 января 2026** включительно.
Прогноз нужно выполнить за тестовый период **с 1 по 28 февраля 2026**.

### Данные

- координаты турбины 1: https://maps.app.goo.gl/iN6svMt69D5qRpFU9 → **43.645150, 78.535604**
- координаты турбины 2: https://maps.app.goo.gl/8UQMwsYavY6nLvFY8 → **43.643198, 78.538828**
- статистическое время;
- средняя скорость ветра, м/с;
- нормализованная активная мощность на стороне линии;
- средняя температура окружающей среды, °C.

### Что должно делать решение

- На основании исторических данных строит модель прогнозирования почасовой выработки.
- **Самостоятельно** получает по координатам ВЭС из открытых источников прогнозы погоды, **доступные на соответствующий момент прогнозирования**.
- Формирует прогноз на следующие 24–48 часов с почасовой детализацией.
- Реализует процесс в формате Agentic AI — система сама выполняет полный цикл:
  получение внешних погодных данных → подготовка данных → запуск модели → формирование почасового прогноза → анализ результата → повторный расчёт при обновлении входных данных.

Выбор источников погоды, ML-моделей, методов обработки и архитектуры агента — за участниками.

### Воспроизведение «как в прошлом»

- на 31 января — прогноз на следующие 24–48 часов;
- на 1 февраля — новый прогноз на следующие 24–48 часов; и так далее последовательно по тестовому периоду.

Для каждого прогноза использовать **архивные прогнозы погоды, доступные на тот момент**, а не фактические значения, ставшие известными позже.

## Что из этого следует для нас

- **50 баллов** — «работает как заявлено» + «можно запустить и проверить». Честность и воспроизводимость важнее числа фич.
- Главная ловушка — утечка данных: взять фактическую погоду вместо прогноза. Жюри это ищет. Мы явно показываем `weatherIssuedAt` для каждого прогноза.
- «Агентность» должна быть реальной: агент принимает решения (проверки, пересчёт, предупреждения), и это видно в журнале шагов.
- Жюри должно запустить проект без наших ключей: локальная LLM (Ollama) + заранее посчитанные результаты в репозитории.
